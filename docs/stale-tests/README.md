# stale-tests/ —— 失效测试隔离目录约定

> 吸收自 `xiwangone/rikkahub-agents` 的工程卫生实践（2026-10-14）。

## 为什么

失效测试（断言了已废弃行为、或依赖已移除能力的测试）有三种处理方式，**只有第三种是可接受的**：

1. ❌ 直接删掉 —— 丢失"曾经为什么这么设计"的线索，后人可能重踩同一个坑；
2. ❌ 留在原地改成恒真/`@Ignore` —— 污染测试输出，掩盖真实失败；
3. ✅ **移入本目录并在文件头写清"为什么失效"** —— 保留语义考古价值，且不再参与 CI。

## 约定

- 文件名沿用原名，前缀加日期：`<yyyy-mm-dd>-<原文件名>`（例：`2026-10-14-FooContractTest.kt.disabled`）。
- 文件头必须写三行：
  ```kotlin
  // STALE: <一句话说明失效原因>
  // REPLACED-BY: <替代它的测试或事实来源；没有就写 NONE>
  // SINCE: <版本号/提交号>
  ```
- **不得**把"只是想跳过"的测试放进来（那属于临时 `@Ignore` + TODO）；本目录只收"契约已合法变更"的测试。
- 从本目录复活某个测试前，先确认 `REPLACED-BY` 是否仍然成立。
