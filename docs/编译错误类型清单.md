# 编译 / CI 错误类型清单（实战版）

> 按出现频率排序，来自 CI 与真机排障的实际日志。骨架吸收自 `xiwangone/rikkahub-agents`，条目按我们的 fork 重写并补充。
> **时效提示**：依赖升级后部分条目可能失效（API 已新增），排查时先验证当前版本。

## 1 · 资源重复定义（AAPT）

**症状：**
```
Error: Found item String/<key> more than one time
```
**原因：** `values/strings.xml` 或 `values-zh/strings.xml` 中同一 key 定义两次（合并代码时最常见）。
**修复：** 删除重复项；语义不同则改用新 key。
**排查：** 两边各应恰好 1 次：
```powershell
Select-String -Path app/src/main/res/values/strings.xml -Pattern "<key>" | Measure-Object
Select-String -Path app/src/main/res/values-zh/strings.xml -Pattern "<key>" | Measure-Object
```

## 2 · Import 缺失（Unresolved reference）

**症状：**
```
e: .../XxxPage.kt:788:79 Unresolved reference 'ViewOff'
```
**原因：** 用到类/图标但未 import；hugeicons 图标必须显式 import。
**规律：** 报错在**使用行** = 缺 import；报错在 **import 行自身** = 类确实不存在（见 §4）。

## 3 · 包名 / 类路径错误

**原因：** 类在子包（例：ML Kit 拉丁模型 `com.google.mlkit.vision.text.latin.TextRecognizerOptions`，中文模型在 `...text.chinese.*`）。
**修复：** 对照官方文档确认完整包路径，或参考仓库内既有用法。

## 4 · API 不存在（版本不匹配）

**症状：** `Unresolved reference 'OutlinedCardDefaults'` 之类。
**修复：** 查当前依赖版本的 API（如 material3 用 `CardDefaults.outlinedCardBorder()`），或参考项目内其他文件写法。

## 5 · @Composable 上下文错误

**症状：** `@Composable invocations can only happen from the context of a @Composable function`
**原因：** 多半是 **API 未解析的连锁反应**（lambda 被当作非 Composable）。
**修复：** 先修根因（补 import / 改 API），此错误通常随之消失。

## 6 · 依赖缺失 / 传递依赖

**症状：** `Error: File google-services.json is missing` 等。
**原因：** 应用了插件但缺配置文件（CI 由 secret 写入）。
**修复：** 本地不要提交该文件；CI 侧确认 secret 注入步骤存在。

## 7 · Room schema / 迁移不匹配

**症状：** CI 报 schema 校验失败，或真机升级后闪退。
**原因：** 改了实体但没升 `version` / 没写迁移；或自动迁移与手写迁移冲突。
**范式（见 `docs/ARCHITECTURE.md` §1.2）**：实体列 + 双向映射 + `version` + 迁移（**手写与自动并存**，Room 按设备版本选路径）+ **实体往返单测**。上游 v28 闪退就是这么来的（已发布版本只写了 `AutoMigration(27→29)`）。

## 8 · 集合相等断言失败（新增工具/能力后）

**症状：** `ToolCatalogTest` / `PrivilegedToolSurfaceTest` / `WorkspaceAndKeyboardCapabilityCatalogTest` / `P2CapabilityCatalogTest` 报集合不相等。
**原因：** 新增工具只改了实现，没同步登记目录/策略/安全面。
**修复：** 按 `docs/ARCHITECTURE.md` **§5 登记清单（8 处）**逐项补齐，并同步 §5 表格里点名的钉死测试。

## 9 · 真机崩溃堆栈里的"合成帧"（不要被误导）

**症状：** 设备日志出现 `kotlin.text.Regex$$ExternalSynthetic...`、`ShizukuDisplayBridgePort$call`、`androidx.transition.ViewUtilsApi19.startUndispatched` 之类**与业务无关**的帧。
**原因：** R8/混淆把不相关的类映射进了堆栈（`r8-map-id` 不同即两次构建）。
**对策：** **只信自家类的帧**（`me.rerere.rikkahub.*`），并回到源码找抛出点；不要照着合成帧猜机制（2026-10-13 曾据此误判成"正则校验 identity"，实际是主键冲突）。

## 10 · 与业务无关的构建噪声

- `LF will be replaced by CRLF` —— Windows 检出提示，无害。
- `--configuration-cache` 相关告警 —— UT 工作流刻意保留 `--no-configuration-cache`（未验证通过前不要打开）。

## 排查流程速查

```
1. 拉 CI 日志：GET /repos/<owner>/<repo>/actions/runs/<id>/logs
2. 找根因：grep "e: file://"        （Kotlin 错误）
          grep "Error: Found"       （资源错误）
          grep "What went wrong"    （任务级错误）
3. 区分：import 行报错 = 类不存在；使用行报错 = 缺 import
4. 修完本地做静态自检（grep 关键符号 + 括号平衡），再推 CI
```
